## 1. Architecture Overview & Guarantees

This implementation plan establishes an **Admin-Only Intelligence & Operations Layer** for **Point 8: Admin Revenue Command Center**.

### Grounding in Existing Foundations:
- **Preserve Point 6 Financial Truth**: Consumes existing `Booking`, `PaymentRecord`, `CommissionLedger`, `PromoCode`, `PromoRedemption`, `ReferralCode`, and `ReferralAttribution` models without redefinition.
- **Strict Formula Consistency**: Reuses authoritative Point 6 formulas:
  - $\text{GBV} = \sum (\text{subtotal} + \text{fee} - \text{discount})$
  - $\text{Local Payables} = \sum \text{subtotal}$ (100% protected)
  - $\text{Net Platform Revenue} = \text{Platform Fees} - \text{Promo Subsidies}$
  - $\text{Effective Take Rate} = (\text{Net Revenue} / \text{Local Payables}) \times 100$
- **Zero New Financial Truth Tables**: Operates purely as a read-model aggregator and settlement batch manager; zero synthetic financial entities.
- **Server-Side Authoritative Truth**: The browser never dictates or calculates financial balances; all metrics, trends, and exports are generated by the backend.
- **Maintain Frozen Scope**: Points 1 through 7 remain 100% frozen.

### 2.2 Backend Analytics & Operations Engine

#### [MODIFY] [`backend/app/main.py`](file:///c:/laragon/www/hirealocals/backend/app/main.py)
Implement core revenue intelligence endpoints protected by `Annotated[User, Depends(admin_user)]`:

1. **Temporal Parsing Helper (`parse_date_window`)**:
   - Parses presets (`today`, `7d`, `30d`, `90d`, `mtd`, `qtd`, `all_time`) or custom (`from_date` / `to_date`).
   - Normalizes UTC start/end boundaries and calculates the exact prior comparison window ($t_{\text{prev\_start}}$ to $t_{\text{prev\_end}}$).
2. **`GET /api/admin/revenue/analytics`**:
   - Computes current executive KPIs and prior comparison deltas ($\Delta\%$).
   - Generates chronological time-series trend buckets (daily for $\le 30\text{d}$, weekly for $\le 90\text{d}$, monthly for $> 90\text{d}$).
   - Aggregates multi-dimensional breakdowns: By City, By Category, By Local Partner, By Promo Code, By Referral Code.
   - Computes payment lifecycle conversion rates (Success, Failure, Refund rates).
3. **`GET /api/admin/revenue/reconciliation`**:
   - Performs relational cross-referencing between `Booking`, `PaymentRecord`, and `CommissionLedger`.
   - Flags discrepancies (`[Matched]`, `[Warning]`, `[Mismatch]`) without modifying database records.
4. **`GET /api/admin/revenue/payout-aging`**:
   - Analyzes mature completed bookings and computes aging days:
     $$\text{aging\_days} = (\text{now}() - \text{booking.completed\_at}).\text{days}$$
   - Groups into `0-7d`, `8-14d`, `15-30d`, and `30d+` overdue buckets.
5. **`POST /api/admin/commission/batch-update`**:
   - Validates multi-record selection (rejecting `void` or `paid` entries).
   - Atomically updates status to `scheduled` or `paid` and records reference notes.
   - Writes `AuditLog` rows for each modified settlement.

## 5. Risk Assessment & Mitigations

| Risk | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **Formula Discrepancies** | Financial metric drift from Point 6 | Reuses identical calculation helpers and formulas from Point 6; tested in E2E suite. |
| **Accidental Ledger Corruption** | Erroneous payout mutations | Reconciliation engine is strictly read-only; batch payout validates eligible statuses with mandatory audit logging. |
| **Performance with Large Datasets** | Slow API response on `all_time` | In-memory stream aggregation using indexed SQLModel queries and bounded date ranges. |
| **Data Leakage in CSV Exports** | Sensitive data exposure | Strict whitelisting of export columns; passwords, tokens, API keys, and KYC records excluded. |
| **Zero Denominator in Comparisons** | ZeroDivisionError on growth rate | Safe division helper returns `0.0%` when prior period metric is zero. |
